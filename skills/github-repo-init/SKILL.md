# GitHub 저장소 초기화

`jaehunshin-git/repo-init`을 기준으로 GitHub 협업 설정을 적용한다. 이 스킬의 목적은 코드 생성이 아니라 라벨과 GitHub 템플릿을 일관되게 배포하는 것이다.

## 요청 해석

다음 자연어 요청을 해당 작업으로 해석한다.

| 사용자 의도 | 작업 |
| --- | --- |
| “이 저장소에 표준 라벨과 이슈·PR 템플릿을 적용해줘” | 기존 저장소에 템플릿을 적용하고 라벨 처리 방식을 확인한다. |
| “기존 라벨은 유지하고 적용해줘” 또는 “라벨만 추가해줘” | 같은 이름의 라벨만 갱신하고, 기존에만 있던 라벨은 유지한다. |
| “라벨을 전부 교체해줘” | 기존 라벨을 삭제한 뒤 표준 라벨 세트를 적용한다. |
| “새 로컬 저장소를 만들어줘” | 로컬 저장소와 템플릿 첫 커밋을 만든다. |
| “비공개/공개 GitHub 저장소까지 만들어줘” | 해당 공개 범위의 원격 저장소를 만들고 라벨·템플릿을 적용한다. |
| “repo-init 스킬을 설치하거나 갱신해줘” | 설치 경로와 기존 설치본을 확인한 뒤 스킬 디렉터리를 설치하거나 갱신한다. |

라벨 처리 방식을 사용자가 밝히지 않으면 **추가·갱신**을 기본값으로 사용한다. 전체 교체는 기존 라벨을 되돌리기 어렵게 삭제하므로, “전체 교체”와 같은 명시적인 요청 또는 확인이 있을 때만 수행한다.

## 실행 전 확인

대상 저장소, 적용할 브랜치, 라벨 처리 방식을 확인한다. 대상이 현재 작업 디렉터리라면 `gh repo view --json nameWithOwner --jq .nameWithOwner`로 식별한다. 원격 변경이나 커밋이 필요한 경우에만 `gh auth status`, Git 사용자 정보, push 권한을 점검한다.

적용 전에 대상의 `.github/ISSUE_TEMPLATE`와 `.github/PULL_REQUEST_TEMPLATE.md`에 미커밋 변경이 있는지 확인한다. 덮어쓸 변경이 있으면 영향을 설명하고 사용자의 방향을 확인한다. 대상의 다른 `.github` 파일은 작업 범위가 아니다.

## 기존 저장소에 적용

템플릿 원본은 `jaehunshin-git/repo-init`이다. 최신 원본이 필요하면 임시 디렉터리에 shallow clone한 뒤 `.github/ISSUE_TEMPLATE`와 `.github/PULL_REQUEST_TEMPLATE.md`만 대상 저장소에 복사한다. 대상의 다른 `.github` 파일은 보존하고 `.DS_Store`는 복사하지 않는다.

라벨은 다음 둘 중 하나만 선택한다.

- **추가·갱신:** `gh label clone jaehunshin-git/repo-init --repo OWNER/REPO --force`를 사용한다. 기존에만 있던 라벨은 유지한다.
- **전체 교체:** 대상 라벨을 모두 삭제한 뒤 같은 clone 명령을 실행한다. 이는 되돌리기 어려운 작업이므로, 삭제 전에 대상과 영향 범위를 명확히 알리고 사용자의 명시적 요청 또는 확인을 받는다.

템플릿 파일이 변경되었을 때만 대상 저장소의 기존 커밋 규칙을 따라 커밋하고 push한다. stage 범위는 `.github/ISSUE_TEMPLATE`와 `.github/PULL_REQUEST_TEMPLATE.md`로 한정하고, `git add .github`처럼 대상의 다른 `.github` 변경을 함께 stage하지 않는다. 커밋 전에 staged diff를 검토한다. 사용자가 원격 변경이나 push를 요청하지 않았다면 파일 변경까지만 수행하고 상태를 보고한다.

## 새 저장소 생성

원본 저장소의 `create-repo.sh`를 사용한다. 신뢰 가능한 사본을 clone한 뒤 다음 형태로 실행한다.

```bash
./create-repo.sh 저장소이름 [--local|--remote] [--private|--public]
```

옵션이 없으면 로컬 Git 저장소와 템플릿 첫 커밋만 만든다. `--remote`, `--private`, `--public`은 GitHub 저장소 생성, 표준 라벨 복제, 템플릿 커밋과 push까지 수행한다. 원격 생성은 외부 상태를 만들며 중간 실패 시 빈 원격 저장소가 남을 수 있음을 먼저 알린다.

## 스킬 설치와 라이선스

스킬 설치 요청에서는 기본 설치 경로 `${CODEX_HOME:-$HOME/.codex}/skills`와 같은 이름의 설치본을 확인한다. 기존 설치본을 삭제하거나 덮어쓸 때는 사용자의 요청 범위를 따르고, 새 설치본의 출처가 `jaehunshin-git/repo-init`인지 확인한다.

이 저장소의 Codex 스킬, Shell 스크립트, GitHub 이슈·PR 템플릿 및 문서는 MIT License에 따라 배포된다. 템플릿을 대상 저장소에 적용해도 그 대상 저장소의 라이선스가 자동으로 MIT가 되지는 않는다.

## 완료 보고

적용한 대상, 라벨 처리 방식, 복사한 템플릿, 생성한 저장소, 커밋·push 여부를 간단히 보고한다. 전체 교체였다면 삭제된 기존 라벨이 있었다는 사실도 함께 기록한다. 원격 생성 또는 라벨 교체가 중간에 실패했다면 남아 있을 수 있는 원격 저장소나 변경 상태를 함께 알린다.
